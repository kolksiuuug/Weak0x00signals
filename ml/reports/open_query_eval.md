# Оценка выдачи по открытому запросу

Сгенерировано: `python -m ml.app.evaluate`. Режим: **offline**. Дата: 2026-09-28T19:22:25+00:00.

Организаторы проверяют решение открытым запросом: по 6 темам датасета выдача сверяется с самим датасетом (CLAUDE.md §0.4). Эти метрики, в отличие от F1 классификатора, заказчик может воспроизвести.

**Режим offline.** Пул кандидатов — датасет организаторов плюс контрольная выборка зрелых и хайповых технологий. Проверяется наша часть: скоринг, фильтр зрелости и ранжирование. Живой поиск по источникам сюда не входит.

**Итого по всем темам:** recall 90.0 % , precision 100.0 % (микро-усреднение: совпадений 90 из 100 размеченных, выдано позиций 90).

### Согласованность порядка выдачи: rho = -0.671

Recall и precision измеряют **состав** ТОП-15. Но сдаём мы ранжированный список, и если на первой позиции стоит наименее интересный из пятнадцати, правильный состав уже не спасает. Поэтому отдельно измеряется **порядок**: корреляция Спирмена между позицией в выдаче и «Баллом» датасета (стадия + тренд, CLAUDE.md §0.3, §1) — единственной внешней истиной про приоритет, которая у нас есть.

Позиция 1 — лучшая, поэтому согласованность означает **отрицательное** rho: −1.0 — порядок в точности повторяет оценку заказчика, 0 — порядок к ней отношения не имеет, положительное — порядок перевёрнут.

Это число появилось не просто так. При прежней формуле ранга (`0.80 × уверенность + 0.20 × фактура`) rho составлял −0.04, то есть порядок был случайным относительно приоритета заказчика, а по теме Edge — прямо перевёрнутым (+0.61): наверх попадали кандидаты с самым низким баллом. Причина в том, что уверенность модели отвечает на вопрос «слабый ли это сигнал», а не «насколько он важен»: стадия концепции со стабильными упоминаниями выглядит максимально «слабой», хотя это балл 3 — низший приоритет. После добавления слагаемого приоритета (`0.50 / 0.30 / 0.20`) на текущем прогоне получено rho = -0.671. Состав выдачи остаётся: recall@15 = 90.0 % и precision@15 = 100.0 %.

## Что не попало в выдачу

**Edge**:

* Агентные (multi-step) AI-workflow, исполняемые локально на NPU ПК

**Защита ИИ**:

* Криптографическая верификация трафика агентов (Web Bot Auth, signed agents)

**Индустриальный ИИ**:

* Нейроморфные/событийные edge-чипы для непрерывного мониторинга промышленного оборудования (мВт-класс, без облака)
* Самообучающиеся контуры управления: RL прямо на промышленном контроллере/в живом цеху (а не в симуляторе)

**Инфраструктура ИИ**:

* 3D-стековая память-вычислитель как альтернатива HBM (3DIMC, стековый DRAM)
* Сверхпроводящие / криогенные вычисления для ИИ-ЦОД

**Роботы**:

* Медицинские микророботы, доходящие до клиники
* Электрогидравлические искусственные мышцы (HASEL) вместо редукторных приводов

**Финтех**:

* Голосовые ИИ-агенты для взыскания и обслуживания долга на развивающихся рынках
* Постквантовая криптография в финансовой инфраструктуре (приоритизация миграции)
