## Что всё ещё зависит от входных данных команды

1. Официальный XLSX на 100 строк отсутствует в переданном ZIP — без него нельзя честно получить финальные метрики обучения на заказчике.
2. Негативные кандидаты не входят в исходные данные и должны быть собраны командой; проект подготовлен под `data/negative_candidates.csv`.
3. API-ключ LLM не был предоставлен в проекте, поэтому без ключа enrichment использует grounded-template. Для финального стенда нужно заполнить `.env` конкретного выбранного провайдера.
4. Для PatentsView нужен отдельный ключ; без него остальные коннекторы продолжают работу.
5. Docker не установлен в текущей среде исполнения, поэтому реальный `docker compose build/up` здесь не выполнялся; проведены статические и локальные проверки Python/конфигурации/фронтенда.

## Что переделать команде до финальной сдачи

- Положить официальный XLSX в `data/official_dataset.xlsx`.
- Заполнить `data/negative_candidates.csv` реальными негативами по 6 темам и зафиксировать основания разметки.
- Запустить `docker compose up -d --build` на VPS, проверить health и live search с открытым запросом.
- Проверить русский вывод LLM на выбранной разрешённой модели и убедиться, что в каждом кейсе все утверждения подтверждаются источниками.
- Передать ключи жюри приватным каналом; не помещать их в Git.
- Сформировать отчёт P/R/F1 после появления реальной train-выборки.
- Перед сдачей проверить презентацию: не более 15 слайдов, 7–11 — исходный шаблон.
