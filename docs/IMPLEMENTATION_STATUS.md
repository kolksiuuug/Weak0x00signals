## Актуальное состояние перед финальной сдачей

1. `data/official_dataset.xlsx` включён в репозиторий и используется для обучения ML.
2. Отрицательный класс зафиксирован в `data/control/mature_control.csv` (45 примеров); он не подмешивается в live-поиск.
3. `.env.example` включён в репозиторий; секретный `.env` не включается в архив сдачи.
4. Пользовательский open search работает только по live открытым источникам; dataset fallback отключён.
5. ML-модель обучается при сборке `ml`-образа; отдельного `ml-trainer` сервиса нет.
6. Перед финальной сдачей на целевой машине необходимо выполнить `docker compose up -d --build`, `/api/health/deep` и несколько реальных open-search запросов.

## Финальная доработка frontend — 29.09.2026

- UI приведён к финальному сценарию ТЗ: свободный запрос → live-поиск → TOP-15 → документ-инсайт.
- Все пользовательские тексты и аналитическая выдача на русском языке.
- В карточке результата отображаются скоринг/уверенность, стадия, динамика, число источников и статус слабого сигнала.
- В документе-инсайте отображаются описание, причина классификации, потенциальное преимущество, кейс, доказательная база, модель/режим, версия модели и проверяемые источники с датой, языком, типом, trust-уровнем и отметкой перевода.
- Добавлен явный блок отклонённых кандидатов с причинами — для демонстрации фильтрации зрелых/нерелевантных сигналов.
- Polling API стал устойчивее к кратковременным 5xx/сетевым сбоям; единичный сбой `/search/{job_id}` не сбрасывает прогресс.
- Таймаут пользовательского ожидания ограничен 180 сек; после него интерфейс сообщает, что backend-задача продолжает работать, вместо бесконечного ожидания.
- `/signal/{id}` используется как дополнительное обогащение карточки: если lookup временно недоступен, пользователь всё равно получает уже найденный результат.
- Кнопки быстрых примеров действительно меняют поисковый запрос и не подменяют результаты mock-данными.
- Добавлена адаптивная вёрстка для ноутбука и мобильной ширины.

## Frontend refresh — 29.09.2026 (score/relevance/style)

- Исправлен эффект изменения confidence/score при открытии карточки: значение `score` фиксируется из исходного результата конкретного search job и не заменяется ответом `/signal/{id}`.
- `/signal/{id}` используется только как enrichment: дополнительные поля могут обновляться, но `id`, `title`, `score` и `dataset_score` исходной карточки сохраняются.
- Основной список фронтенда сортируется по зафиксированному score по убыванию.
- Добавлен UI relevance-gate: при деградации contextual rerank/LLM фронтенд скрывает очевидно нерелевантные документы без изменения серверного job; пользователю показывается явная пометка `RELEVANCE GATE`.
- Это защищает пользовательскую выдачу от очевидных тематических выбросов вроде публикаций о кормлении животных при запросе про промышленный ИИ, когда серверный fallback классифицирует документ слишком широко.
- Карточки сделаны `type="button"`, чтобы клики не могли инициировать побочные submit-сценарии.
- Визуальный стиль обновлён: более строгая исследовательская консоль, графитовый фон, светло-зелёный акцент, плотные карточки, более выраженная иерархия метаданных, новые hover/focus состояния и мобильная адаптация.

## Search stability + contextual gate — 29.09.2026

- Убрано LLM-expansion из arXiv collect по умолчанию: расширение запроса теперь детерминированное и не создаёт обращения к GigaChat.
- Убраны contextual LLM rerank и отдельный LLM context-validator из каждого search job. Перед ML ranking работает обязательный тематический context gate по исходному запросу и реальному `title/raw_text`.
- Для составных тем все распознанные тематические якоря должны присутствовать в документе. Для запроса «промышленный ИИ» одновременно требуются признаки промышленной области и AI. Это отбрасывает документы вроде исследований пробиотиков для птицы независимо от ошибочного `area`.
- Убран массовый `/enrich` для TOP-15 после каждого поиска. Enrichment остаётся ленивым, но Docker Compose включает его по умолчанию (`LLM_LAZY_ENRICHMENT=true`) для открываемой карточки; при отсутствии ключа/лимите работает grounded fallback без LLM.
- GigaChat получил кеш OAuth-токена, single-flight lock и cooldown после 429. Повторные запросы во время rate limit не отправляются.
- Score карточки больше не пересчитывается при открытии `/api/signal/{id}`: сохраняется score конкретного search job.
- Frontend полностью переведён из neon/cyber-dashboard в спокойный editorial research UI: светлая бумажная палитра, типографика, таблица результатов, аккуратные метрики, без декоративных «AI» графиков.
- Docker Compose явно фиксирует `LLM_SEARCH_EXPANSION=false`, `LLM_LAZY_ENRICHMENT=true` и `LLM_REQUIRED=false` по умолчанию.
