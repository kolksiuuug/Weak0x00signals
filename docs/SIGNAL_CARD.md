# Карточка сигнала: обязательное содержимое

Карточка сигнала должна быть содержательной даже при недоступности LLM.

## Поля

- **Описание** — extractive summary из заголовка и доступных аннотаций найденных источников. Нельзя придумывать факты, которых нет в источниках.
- **Почему это слабый сигнал** — объясняет раннюю стадию, динамику и объём независимого подтверждения. Это не должно быть пустой строкой.
- **Потенциальное преимущество** — только явно наблюдаемый эффект из текста источников.
- **Кейс-пример** — конкретное испытание/пилот/внедрение, если оно явно встречается в аннотации; иначе честно указывается отсутствие кейса.
- **Почему релевантен запросу** — тематические якоря и область запроса.
- **Источники / trust level** — все источники, объединённые в одну тематическую карточку.

## Почему раньше появлялись заглушки

Live-поиск строит карточки до LLM-enrichment. В старой реализации `_russian_card_fallback()` заполнял `description`, `advantage` и `case_example` общими шаблонами, но **не заполнял `why`**. Поэтому UI показывал «Объяснение классификации не передано». Кроме того, описание почти не использовало текст аннотаций.

Теперь fallback получает `raw_text` группы источников и формирует содержательное описание, преимущество, кейс и объяснение слабости без внешних фактов. LLM остаётся дополнительным grounded-enrichment, а не единственным источником текста карточки.
