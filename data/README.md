# Каталог данных

## Структура

```
data/
├── raw/         # исходники КАК ЕСТЬ: .xlsx от организаторов. В .gitignore.
├── processed/   # чистый датасет после нормализации (CSV/parquet). В .gitignore.
└── control/     # контрольная выборка отрицательного класса. В git — это часть методологии.
```

## Куда класть датасет организаторов

Положите файл организаторов (лист «Слабые сигналы», 100 строк) сюда:

```
data/official_dataset.xlsx
```

Имя файла не критично — загрузчик `ml/app/dataset.py` сам находит первый `.xlsx`
в `data/`, а внутри него — лист «Слабые сигналы» (или первый лист, если такого нет).
Путь можно задать явно: `--dataset data/official_dataset.xlsx`.

**Файл в репозиторий не коммитится** (`.gitignore`): это единственные исходные данные, полученные от заказчика.

## Ожидаемые колонки (CLAUDE.md §1)

`Технология`, `Область`, `Компании`, `Почему это слабый сигнал`, `Стадия развития`,
`Тренд упоминаний`, `Балл (стадия+тренд)`, `Источники`.

Загрузчик сопоставляет колонки нечётко (по нормализованному имени), поэтому мелкие
расхождения в написании заголовков и порядке колонок не ломают пайплайн.
