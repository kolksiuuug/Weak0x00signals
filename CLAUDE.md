## 1. О проекте

Мы делаем **сервис автоматического поиска «слабых сигналов»** — ранних, малозаметных
научно-технологических трендов — по открытым источникам. Хакатон Газпромбанк.Тех.

Решение состоит из **двух этапов**:

1. **Этап 1 — обучение на закрытом датасете.** Интерпретируемая модель, которая детектирует
   «слабость» сигнала. Метрики Precision / Recall / F1, **порог точности ≥ 75–80 %**. Модель
   обязана показывать, **по каким признакам** наблюдение отнесено к слабому сигналу.
2. **Этап 2 — открытый RAG-пайплайн (главная часть).** Свободный запрос пользователя →
   поиск по живым открытым источникам → скоринг → **фильтр зрелых/хайповых технологий** →
   **ТОП-15 гипотез на русском** (описание, преимущество, кейс-пример, источники, объяснение).

### Ключевой инсайт по датасету (важно для всех ассистентов)

Датасет — 100 строк, лист «Слабые сигналы». Колонки: `Технология`, `Область` (6 сбалансированных:
Индустриальный ИИ, Инфраструктура ИИ, Роботы, Финтех, Защита ИИ, Edge), `Компании`,
`Почему это слабый сигнал`, `Стадия развития`, `Тренд упоминаний`, `Балл (стадия+тренд)` (3–7),
`Источники` (1–3 ссылки).

**Целевой «Балл» на 99 % воспроизводится как сумма двух порядковых признаков:**

| Стадия развития | балл | | Тренд упоминаний | балл |
|---|---|---|---|---|
| Концепция/Исследование | 1 | | стабильно / иное | 1 |
| Прототип/PoC | 2 | | растёт | 2 |
| Пилот | 3 | | растёт быстро | 3 |
| Раннее внедрение | 4 | | | |

`Балл = стадия + трен­д` (диапазон 3–7). **Отсюда прямое следствие: модель этапа 1 должна быть
простой и прозрачной (scikit-learn на инженерных признаках). НЕ файн-тюним LLM. НЕ строим
нейросеть на 100 строках.** Это же и есть требуемая интерпретируемость.

## 2. Железные правила проекта (нарушение = провал на защите)

Эти правила действуют для **всех участников и всех ассистентов**. Ассистент обязан отказаться
от решения, которое их нарушает, и предложить корректную альтернативу.

1. **Язык:** Python **3.8+**. Весь пользовательский интерфейс и вся аналитическая выдача — **на русском**.
2. **Модель этапа 1 — интерпретируемая (scikit-learn).** Без файн-тюна LLM, без тяжёлого DL.
3. **RAG обязателен.** Итоговая выдача формируется **только по реально найденным и проверенным
   источникам.** Генерация сигналов «из головы» LLM без подтверждённого поиска — **дисквалификация.**
4. **LLM только из белого списка ТЗ:** `GigaChat 2 Lite/Pro/Max`, `YandexGPT Lite 5`,
   `YandexGPT Pro 5/5.1`, `Qwen3.6 35B-A3B`, `Qwen3 235B`, `gpt-4.1`, `gpt-5.6-luna`.
   **Запрещено:** OpenRouter и прочие роутеры, автовыбор модели, нераскрытые модели. Локальные
   модели — любые с Hugging Face. Формат выбора модели должен логироваться.
5. **База данных:** **PostgreSQL** (сырые данные + результаты). Вектора — через `pgvector`.
6. **Архитектура:** чёткое разделение слоёв **парсинг / инференс / интерфейс**. Всё упаковано в
   **Docker** (раздельные сервисы, `docker-compose`).
7. **Каждый источник** обязан отдавать: `наименование, ссылку, дату публикации, тип источника,
   язык оригинала, уровень доверенности`.
8. **Доверенность источников:** соцсети, личные блоги, агрегаторы, анонимные ресурсы, реклама,
   пресс-релизы = **пониженная доверенность** и **не могут быть единственным основанием** для
   включения технологии в выдачу.
9. **Зарубежные источники:** давать **русскоязычное резюме/интерпретацию**, сохраняя оригинальные
   название, ссылку, дату, язык. Если использован автоперевод или генеративное резюме — **пометить это.**
10. **Фильтр зрелости:** зрелые технологии, массовое внедрение, отраслевые стандарты,
    сформированные рынки с лидерами, маркетинговый хайп и инфошум — **исключаются**, с **явной
    причиной отклонения по каждому кандидату** (жюри отдельно оценивает обоснованность исключения).

## 3. Контракт данных (единая схема между модулями)

**Все модули работают с этой схемой. Менять её можно только по согласованию всей команды**
(в общем чате), с обновлением этого файла. Это граница, через которую участники не блокируют друг друга.

```python
from enum import Enum
from typing import Optional
from pydantic import BaseModel, HttpUrl


class SourceType(str, Enum):
    SCIENTIFIC = "научная_статья"
    PATENT     = "патент"
    NEWS       = "новость"
    ANALYTICS  = "аналитический_отчёт"
    REGISTRY   = "гос_реестр"
    BLOG       = "блог"
    SOCIAL     = "соцсеть"
    PRESS      = "пресс_релиз"


class TrustLevel(str, Enum):
    HIGH   = "высокий"       # гос/регуляторы/университеты/научные публикации/патенты
    MEDIUM = "средний"       # отраслевые медиа, аналитика
    LOW    = "пониженный"    # соцсети/блоги/пресс-релизы — не единственное основание


class Source(BaseModel):
    title: str
    url: HttpUrl
    date: Optional[str] = None        # ISO 8601 или None, если даты нет
    source_type: SourceType
    language: str                     # "ru", "en", ...
    trust_level: TrustLevel
    translated: bool = False          # True → есть автоперевод/генеративное резюме (пометка)


class SignalDoc(BaseModel):
    id: str
    title: str                        # название технологии-кандидата
    area: Optional[str] = None        # одна из 6 областей или свободная тема
    companies: list[str] = []
    raw_text: str                     # нормализованный текст источника(ов)
    stage: Optional[int] = None       # 1..4 (см. таблицу инсайта)
    trend: Optional[int] = None       # 1..3
    score: Optional[float] = None     # уверенность модели / балл
    why: Optional[str] = None         # объяснение: почему это слабый сигнал (интерпретируемость)
    is_weak_signal: Optional[bool] = None
    rejected_reason: Optional[str] = None   # причина, если отсеян фильтром зрелости/хайпа
    sources: list[Source] = []
```

Эндпоинты API (стабильный контракт для фронта):
`POST /search` (свободный запрос → ТОП-15) · `GET /signal/{id}` (карточка-инсайт) · `GET /sources` (проверка источников).

## 5. Правила совместной работы (для трёх разных ассистентов)

Поскольку каждый пилит свой модуль своим ИИ, дисциплина границ критична.

- **Работаем на моках.** Пока чужой модуль не готов — используем заглушки по схеме из §3. Никто никого не ждёт.
- **Границы модулей.** Свой каталог правишь свободно; **чужой каталог не трогаешь** без согласования.
  Общий код (схема `SignalDoc`, конфиги) меняем только через общий чат + правку этого файла.
- **Git.** Ветки `feat/<роль>-<задача>`, PR в `main`, без прямых пушей в `main`. Коммиты по
  Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`).
- **Секреты.** Ключи LLM и БД — только в `.env` (в `.gitignore`). В `.env.example` — пустые заглушки.
  **Никаких ключей в коде, коммитах и в диалогах с ассистентом.**
- **Дейли 15 минут:** сделал / делаю / где заблокирован.
- **Инструкция ассистенту:** если предлагаешь решение, которое нарушает §2 — **остановись и скажи об этом.**

## 6. Роли и границы

### 👤 Участник 1 — тимлид / архитектура + backend + frontend + ИБ
**Навыки:** Docker, Node/Express, Python, PHP, React, архитектура, ИБ.
**Каталоги:** `/api`, `/frontend`, `docker-compose.yml`, корневые конфиги.
**Отвечает за:**
- Каркас монорепо, `docker-compose` (раздельные сервисы), `.env.example`, README с Docker-командами.
- FastAPI: эндпоинты `/search`, `/signal/{id}`, `/sources`; сборка ответа из модулей коллег.
- **ИБ/trust-слой (уникальный вклад, оценивается жюри):** классификатор доверенности
  (`тип + домен → TrustLevel`), дедуп по URL, санитайзинг парсинга, **логирование выбора модели и источников.**
- React к финалу: поиск → таблица ТОП-15 (технология, скоринг, предикторы, статус) →
  карточка-инсайт (документ-отчёт) + статистика (обработано источников; число сигналов с уверенностью >75 %).
- Финал: развёрнутый демо-стенд, схема архитектуры (PlantUML/draw.io).

**Получает:** нормализованные `SignalDoc` (У3), готовый скоринг/ранжирование (У2).
**Отдаёт:** стабильный API-контракт и UI. **Не трогает:** внутренности `/ml` и `/parser`.
**На защите:** архитектура + живое демо.

---

### 👤 Участник 2 — ML-ядро + база данных
**Навыки:** Python, C#, PostgreSQL, C++, Java.
**Каталоги:** `/ml`, схема БД.
**Отвечает за:**
- Схема PostgreSQL (`documents`, `signals`, `sources`) + подключение `pgvector`.
- **Модель этапа 1 (scikit-learn, НЕ нейросеть):** кодировка стадии (1..4) и тренда (1..3) + признаки
  «слабости» (разреженность публикаций, малые команды, seed-раунды, концентрация игроков);
  LogReg/GradientBoosting; **Precision/Recall/F1 (цель F1 ≥ 80 % на hold-out)** + feature importance в Jupyter.
- Инференс-модуль `score(doc) -> (score, why)` поверх схемы §3.
- **Фильтр зрелости/хайпа** с явной `rejected_reason` по каждому кандидату; калибровка скоринга.
- Формирование **ТОП-15** (ранжирование + предикторы в объяснении).
- Промежуточная сдача: отчёт по метрикам + описание методологии.

**Получает:** чистый датасет и живые документы (У3).
**Отдаёт:** `score`, `why`, `is_weak_signal`, `rejected_reason`, ТОП-15 (У1). **Не трогает:** `/api`, `/frontend`, `/parser`.
**На защите:** методология + метрики.

### 👤 Участник 3 — парсеры / источники + LLM-сервис + датасет
**Навыки:** Python, Java.
**Каталоги:** `/parser`, `/data`.
**Отвечает за:**
- День 1: очистка датасета из `.xlsx` → чистый CSV/parquet (распарсить markdown-ссылки,
  нормализовать «стадию»/«тренд») → фикстура для У2.
- **Коннекторы** (каждый = «скачать → нормализовать в `SignalDoc`»): arXiv API, Crossref/OpenAlex,
  GDELT (новости), PatentsView (патенты), `trafilatura` для статей. **Ретраи, таймауты, деградация**
  (упал один источник — пайплайн продолжает). Дедуп. **Официальные API вместо скрейпинга, где есть.**
- **LLM-сервис** с чистым интерфейсом: `summarize_ru`, `translate_ru` (с пометкой «автоперевод»),
  `generate_hypothesis` — **строго по найденным источникам.**
- Простановка `TrustLevel` по §2/§3; кэш результатов (чтобы демо не тормозило).
- Генерация текста инсайта (описание, преимущество, кейс, объяснение статуса) по источникам.

**Получает:** от У2 — что подавать в LLM. **Отдаёт:** чистый датасет (У2), нормализованные `SignalDoc` (У1/У2).
**Не трогает:** `/ml`-модель, `/api`-роутинг, `/frontend`. **На защите:** источники + пайплайн.

## 7. Красные флаги — ассистент обязан отказаться и предупредить

- ❌ Файн-тюн LLM или тяжёлая нейросеть «для точности» на 100 строках → используем scikit-learn (см. §1).
- ❌ Формирование итоговых сигналов из знаний LLM без реального поиска по источникам → дисквалификация (§2.3).
- ❌ Модель вне белого списка, OpenRouter, автовыбор модели → §2.4.
- ❌ Источник без полного набора метаданных (`name/url/date/type/language/trust`) → §2.7.
- ❌ Включение технологии только на основе соцсети/блога/пресс-релиза → §2.8.
- ❌ Зарубежный источник без русского резюме и пометки об автопереводе → §2.9.
- ❌ Молчаливый фильтр зрелости без `rejected_reason` → §2.10.
- ❌ Английский текст в выдаче или UI → §2.1.
- ❌ Секреты/ключи в коде или коммитах → §5.
