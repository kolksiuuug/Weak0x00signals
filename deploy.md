# Weak0x00 Signals — методичка по локальному развёртыванию

## 1. Назначение

Данная инструкция предназначена для локального запуска проекта **Weak0x00 Signals** перед демонстрацией жюри.

Проект запускается на компьютере организатора через Docker Compose и доступен локально в браузере.

Для локальной демонстрации не требуются:

* VPS;
* публичный IP-адрес;
* домен;
* Nginx Proxy Manager;
* настройка HTTPS;
* внешний reverse proxy.

После запуска интерфейс доступен через:

```text
http://localhost:18080
```

или:

```text
http://127.0.0.1:18080
```

# 4. Подготовка конфигурации

В проекте используется файл `.env`.

Если `.env` ещё отсутствует, создать его на основе шаблона:

```bash
cp .env.example .env
```

Открыть файл:

```bash
nano .env
```

или:

```bash
cat .env
```

Для локальной демонстрации необходимо убедиться, что задан непустой пароль PostgreSQL:

```env
POSTGRES_PASSWORD=your_password
```

Можно использовать любой пароль, предназначенный именно для локального демонстрационного запуска.

Например:

```env
POSTGRES_PASSWORD=weak-signals-demo
```

> Не следует использовать реальные production-пароли или секреты в демонстрационной конфигурации.

---

# 5. Запуск проекта

Из корневого каталога проекта выполнить:

```bash
docker compose up -d --build
```

Docker соберёт необходимые образы и запустит контейнеры проекта.

Проверить состояние контейнеров:

```bash
docker compose ps
```

Все основные сервисы должны находиться в состоянии `Up` или `running`.

Для просмотра логов:

```bash
docker compose logs -f
```

Для выхода из режима просмотра логов нажать:

```text
Ctrl+C
```

Это не останавливает контейнеры.

# 8. Что демонстрировать жюри

Рекомендуемый сценарий демонстрации:

### 1. Поиск

Показать, что пользователь вводит технологическую тему.

Например:

```text
AI agents
```

### 2. Сбор источников

Показать, что система работает с несколькими научными источниками.

Используются:

* arXiv;
* OpenAlex;
* Crossref.

### 3. Объединение результатов

Показать карточку, содержащую несколько источников по одной теме.

Это демонстрирует, что система не просто выводит отдельные результаты поиска, а объединяет связанные материалы.

### 4. Объяснение сигнала

Открыть карточку и показать отдельно:

**Почему слабый сигнал**

и:

**Почему релевантен запросу**

Эти поля решают разные задачи:

```text
why
```

объясняет признаки слабого сигнала.

```text
relevance_reason
```

объясняет связь найденной темы с исходным запросом.

### 5. Доказательная база

Показать:

* источники;
* согласованность источников;
* trust level;
* evidence summary.

### 6. ML

Показать техническую информацию о модели:

```text
Режим: обученный
Версия: logreg-l2-v4
```

# 13. Остановка после демонстрации

Чтобы остановить контейнеры проекта:

```bash
docker compose down
```

Это останавливает и удаляет контейнеры текущего Compose-проекта.

Данные PostgreSQL, находящиеся в Docker volumes, при обычном выполнении `docker compose down` не удаляются.

Не следует использовать:

```bash
docker compose down -v
```

без необходимости, поскольку `-v` удаляет volumes и может привести к потере данных PostgreSQL.

# 16. Важное отличие локального запуска от VPS

Проект также содержит `deploy-vps.sh`, предназначенный для развёртывания на VPS, где уже работает Nginx Proxy Manager.

Для локальной демонстрации этот сценарий не требуется.

Локальный запуск использует непосредственно Docker Compose:

```text
Браузер
   ↓
localhost:18080
   ↓
Weak0x00 Signals
   ↓
Docker Compose
   ↓
API / Parser / ML / PostgreSQL
```

VPS-развёртывание дополнительно использует:

```text
Интернет
   ↓
Domain
   ↓
Nginx Proxy Manager
   ↓
weak-signals:8080
   ↓
Weak0x00 Signals
```

Таким образом, локальная демонстрация не зависит от доступности VPS или домена.

# 17. Типовые проблемы

## Docker не запущен

Проверить:

```bash
docker info
```

Если Docker daemon недоступен, необходимо запустить Docker.

---

## Порт 18080 занят

Проверить:

```bash
sudo ss -ltnp | grep 18080
```

Если порт занят другим приложением, необходимо освободить его либо изменить локальный порт в конфигурации проекта.

---

## Контейнер завершился с ошибкой

Проверить:

```bash
docker compose ps
```

Затем:

```bash
docker compose logs --tail=200
```

---

## Health check не отвечает

Проверить состояние:

```bash
docker compose ps
```

Затем посмотреть логи:

```bash
docker compose logs --tail=200
```

Особое внимание следует обратить на API, parser и PostgreSQL.

---

## Необходимо полностью пересобрать проект

Выполнить:

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

Удалять volumes без необходимости не следует.
